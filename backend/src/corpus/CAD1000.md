# CAD 1000 Hours knowledge corpus

`src.corpus.cad1000` converts selected textual artifacts in
`markov-ai/cad-1000-hours` into local design-intent records. By default it uses
the mechanically relevant SOLIDWORKS, CATIA, and Siemens NX workflows; generic
drafting, architecture, BIM, structural-analysis, and rendering workflows are
excluded. It does not download videos, event streams, inputs, or completed CAD
files.

## Safety and product boundary

- The source contains workflow demonstrations, not verified manufacturing
  physics or measured shop outcomes.
- Every record is tagged `THIRD_PARTY_UNVERIFIED` and
  `may_affect_deterministic_verdict: false`.
- Every record declares `engineering_authority: NONE`, a constrained
  `allowed_uses` list, and the manufacturing decisions it is forbidden to make.
- The dataset currently declares no license. Records therefore default to
  `eligible_for_training: false` and
  `eligible_for_production_retrieval: false`.
- `WorkflowKnowledgeBase` always rejects records that claim engineering
  authority or verdict influence. Normal retrieval additionally requires both
  explicit rights clearance and a non-undeclared license.
- License clearance must be represented by a reviewed code/data change; do not
  edit generated JSONL flags by hand.

This preserves CadVerify's platform contract: retrieved evidence can help infer
design intent, interpret requirements, and explain redesign options, but only
the deterministic engine may produce a makeability verdict or a
provenance-bearing engineering number.

## Rights-cleared textual pilot

From `backend/`:

```bash
.venv/bin/python -m src.corpus.cad1000 \
  --manifest ../data/knowledge/cad1000-manifest.json \
  --limit 3
```

The manifest must explicitly grant `rights.local_research: true`; otherwise the
command exits before any dataset request or output write. The default output is
`data/knowledge/cad1000.jsonl`, under the existing local
data root. Use `CADVERIFY_DATA_DIR` to redirect it. The write is atomic: an
interrupted download does not replace the last usable snapshot.

Inventory the complete pinned source without downloading its 256.62 GiB of
payloads:

```bash
.venv/bin/python -m src.corpus.cad1000_manifest
```

The resulting `data/knowledge/cad1000-manifest.json` reconciles every artifact,
byte count, workflow, upstream hash (when supplied), media type, frozen workflow
split, and per-use rights decision. Upstream hashes remain explicitly
unverified until a local mirror is hashed; undeclared rights fail closed for
production retrieval, training, and redistribution.

## Full offline refinery

Once an authorized local mirror exists and its reviewed manifest explicitly
grants `rights.local_research: true`, refine all mechanical workflows without
copying raw video, typed text, window titles, network identifiers, or file paths
into the served corpus:

```bash
.venv/bin/python -m src.corpus.cad1000_refinery \
  --manifest ../data/knowledge/cad1000-manifest.json \
  --mirror /path/to/pinned-local-mirror \
  --output ../data/knowledge/cad1000-refined
```

The command hashes and size-checks every local source against the pinned
manifest, writes one atomic resumable shard per workflow, and then writes an
atomic combined `cad1000-refined.jsonl`. Raw video remains an offline-only
timestamp pointer. Raw event and frame-event files become fixed-vocabulary
counts and narration timing aggregates. Native proprietary CAD receives only
verified artifact metadata; a geometry delta is produced only for a local STL
before/after pair whose geometry can actually be parsed. Any incomplete,
malformed, or mismatched workflow is quarantined without aborting the rest.
If `local_research` is not explicitly granted, the refinery exits before it
reads or writes any raw artifact; there is no command-line override.

Run the curated cross-workflow holdout after building the textual corpus:

```bash
.venv/bin/python -m src.eval.cad1000_retrieval \
  --corpus ../data/knowledge/cad1000.jsonl \
  --queries src/eval/cad1000_retrieval_queries.json \
  --research
```

`--research` is mandatory while rights remain undeclared; production retrieval
continues to fail closed.

## Record types

- `workflow`: task, description, application, domain, and deliverables.
- `rubric`: one supplied completion criterion per record.
- `workflow_segment`: action, intent, details, and exact start/end timestamps.

Their corresponding `knowledge_role` values are `design_intent`,
`design_requirement`, and `authoring_trace`. Import a non-core application only
for a deliberate evaluation with `--application`; use `--all-software` only for
generic-CAD research.

The timestamp fields let the advisory finding disclosure deep-link to the
corresponding source interval.

To exercise that disclosure locally, enable `DESIGN_INTELLIGENCE_ENABLED=1` and
`CAD1000_RESEARCH_MODE=1` in the backend and
`NEXT_PUBLIC_DESIGN_INTELLIGENCE=1` in the frontend. Research mode is ignored
when `RELEASE` identifies a production build.
